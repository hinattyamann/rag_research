# 独立品質確認の基準とDevelopment練習例

Version: order-quality-pilot-v1。作成日: 2026年10月18日。
Phase 7の開発用基準であり、本実験の最終凍結ではない。最終版はCalibrationを経てPhase 11で固定する。
[研究計画](rag_research_plan.md)と[Phase 7 Protocol](phase7_order_protocol.md)に従う。

## 1. 誰が何を判定するか

研究者本人が、質問、回答候補、実使用Context、Reference/Gold根拠を確認する。
条件名、順序、自己評価Score、判断、初回/書換えの区別、JudgeのClaimや判定理由は表示しない。
Referenceだけを正解の唯一の表現とせず、候補の意味と根拠を確認する。
自動採点は下書きとして使えても、人手確認済みLabelと混同しない。参加者を募集する操作評価ではない。

## 2. 判定手順

1. 質問が求める対象・時点・条件を確認し、必須の要点を記録する。
2. 回答が必須要点へ実質的に答えているか確認する。引用IDだけ、無関係な説明、質問の言い換えだけでは不足する。
3. 重大な事実誤り・条件や例外の脱落・矛盾がないか確認する。
4. 回答中の事実の主張が、モデルに実際に渡したContextで支持されるか確認する。
5. 下表のLabelと、理由・根拠ID/原文箇所を記録する。自己評価の結果を根拠にLabelを決めない。

| Label | 定義 |
|---|---|
| reliable / Y=1 | 必須要点を満たし、重大な事実誤りがなく、事実主張が実使用Contextに支持される |
| unreliable / Y=0 | 明確な不足・誤り・非支持・不適切な拒否の少なくとも一つを確認できる |
| indeterminate / Y=null | 質問の曖昧さ、Reference不整合、根拠の矛盾等で合理的な判定ができない |

単に採点作業が未完了なら`pending`とし、`indeterminate`と区別する。
一つの明確な失敗条件だけでY=0を確定できる場合、他の全観点が判定可能である必要はない。
一方、唯一の失敗らしき点が曖昧な場合は、その曖昧さを無理にY=0へ変換しない。

## 3. 境界例（説明用に作った例。実験データではない）

質問「日曜日に開館していますか」、実使用Context「日曜休館」の場合:

| 回答 | 練習Label | 理由 |
|---|---|---|
| 日曜日は休館です | Y=1 | 必須要点に答え、根拠がある |
| 日曜日も開館しています | Y=0 | 根拠と矛盾する |
| この施設は地域の文化施設です | Y=0 | 質問への答えがない。事実の支持だけでも足りない |
| [文書ID] | Y=0 | 引用だけで回答の主張がない |

「日曜開館」と「日曜休館」が両方あり、対象施設・時点の違いを解決できない例は、
判定不能の候補である。文書の先頭位置だけでどちらを正しいと決めない。

### 例1: 回答が引用だけになった場合

- Record ID: `clapnq:c508d78:train:-2421097959159398117:answerable`
- 質問: `who proposed that atoms are the basic units of matter`
- 保存された回答: `[845305320_4200-4964] [803775631_38239-38869]`
- 実使用根拠: AtomやHistory of chemistryの文書を含む。
- 点検点: 引用IDだけでは「誰が/どの由来か」を伝える文章がなく、回答の実質的内容が不足している。
- 注意: Referenceは古代文化と19世紀の発展を述べ、質問の「誰」と完全には一致しない。
  直接の人名解答を一つへ固定する前に、質問・Reference・複数の取得根拠を確認する。
- Phase 7の基準案: 引用だけの不足は明確なY=0候補。一方、事実Claim抽出は空配列が妥当な候補である。
  Fを満点へ変換して「高品質」と認定しない。
- 最終の人手Label: **pending**。ここでの基準案を確定済みAnnotationと数えない。

### 例2: 支持される周辺説明でも、質問に答えているとは限らない場合

- Record ID: `clapnq:c508d78:train:-996127241617807228:answerable`
- 質問: `what does prada mean in the devil wears prada`
- 保存された回答の内容: 題名の各国語訳とイタリア語題名について説明している。
- 実使用根拠の一つ: `834292919_54767-55759`（題名の翻訳に関する段落）。
- Referenceの内容: 衣装にPradaが使われたこと、とくにStreepの靴の約40%という記述。
- 点検点: 題名の翻訳説明が根拠に支持されても、質問の意図・必須要点を満たすとは限らない。
  質問の意味とReferenceの対応に曖昧さがあるため、表現不一致だけでY=0にしない。
- Phase 7の基準案: 質問意図と必須要点を解決できなければ`indeterminate`候補。
  Gold未取得だけで「根拠なし」や「回答は誤り」を確定しない。
- 最終の人手Label: **pending**。人手確認前に、曖昧例を確定した失敗例へ数えない。

## 5. 保存と集計

採点用ID、候補Hash、基準Version、必須要点、支持/誤り/不足の理由、根拠箇所、Label、確認者、時間を保存する。
同じ質問・同じ候補・同じContextにはLabelを共用する。質問や本文が変われば再確認する。
初回/書換えの両Labelが確定した共通QAで四遷移を求め、未知数・理由を併記する。
`pending`と`indeterminate`を隠さず、分母0は適用対象外。未知を良い/悪い側へ振った感度も示す。
単独採点のため、評価者間一致や完全な盲検が得られたとは主張しない。
