# Phase 11 評価器の精査・研究資源・テストの見直し

2026-10-24追記: [研究室での週末自律継続Goal](phase11_lab_weekend_goal.md)により、今後の新規作業では
候補1個/188試行/4時間/回復可能障害時Goal停止の方針を置換できる。本文の旧台帳・旧不採用は保存し、
二値各90%・Health・被覆・未使用性・全採点封印は維持する。旧Guardの迂回ではなく、新Versionの実装/検証/登録が必要。

決定日: 2026-10-23。ユーザーの「改善に時間をかけすぎず、妥協範囲と引継ぎを決める」という依頼に基づく。
**設計決定時は未実装。その後の実装・事前登録は[基準v2](phase11_binary_adoption_v2.md)による。旧Runの採否は変更しない。**
現行v1のGuardを迂回してMainを開始する許可ではない。次チャットで別Versionへ実装・検証し、
新規Main/予約Calibrationの結果を見る前に条件を事前固定する。

## 1. 改善を続けるべき範囲

研究目的は、固定した評価器について根拠順序と同一順序反復の差、採用/一回書換え・独立回答品質・費用への影響を測ること。
評価器の正確性向上自体を卒論の主目的へ置き換えない。誤支持や支持の見落としを放置してよいという意味でもない。
順序感度が大きい/小さい、有意/非有意のどちらも採用条件にしない。

コードのFは`支持された固定文数 / 全固定文数`で、contradictedとnot_supportedはどちらも分子へ加算されない
（`src/rag_research/evaluation/claimwise.py`）。したがって、両者間だけの取り違えを直すために
候補の全面再試行を繰り返す費用対効果は低い。主に精査するのは、支持/非支持の誤り、実際のF/判断、回答品質への波及である。
3分類の誤りや不適切な理由は二次診断として全件残す。

## 2. 妥協できる部分と維持する部分

| 対象 | 今後の扱い | 根拠・制限 |
|---|---|---|
| CとNSの完全一致 | 新Protocolの主採用条件から外し、3分類精度を併記 | 両方が非支持ならF/一回書換え判断は同じ。Expected自体は変更しない |
| 支持/非支持の妥当性 | 主採用指標として維持 | 誤支持と支持見落としはFを変え得る |
| 誤支持0の要求 | 新Protocolでは下記のクラス別基準へ変更する設計 | 観測誤り0を母集団の誤り0と解釈しない。旧不採用を通過へ書き換えない |
| 人工27例の元/逆2回 | 同一入力なら新開発Smokeは各1回でよい | 1文書/同じSeedの重複。全27例を保持し、都合のよい側を選ばない |
| 実QAの順序条件と反復 | 維持 | 5順序/5同一順序反復・元順序共有の最大9試行は研究の比較対照 |
| 過去の形式/Hash証拠 | 関連条件が不変なら再利用 | Model/Runtime/Sampler/Schema/実装の変更に応じた再検証とBindingが必要 |
| 全pytestの頻度 | 実装変更時と最終検証で実施 | 約30秒の全761 Testを削っても数十時間の推論は削れない。文書だけの変更では機械的に反復しない |
| 全文/固定文、ID、分母 | 妥協しない | 根拠順序以外の操作や都合のよい補充を防ぐ |
| JSON破損、入力超過、未知応答、CUDA停止 | 実採用では許容しない | 誤ラベルと実行失敗を混同しない。未知を非支持0や費用0へ置換しない |
| 未使用Cal/Evaluation隔離、全採点封印 | 妥協しない | 調整と検証の分離、内部Fを見ない品質採点を守る |

## 3. 新Protocolで実装する意味採用の設計値

元の3分類Label/Expected/全Rawを保持し、別の派生集計だけでS対非Sへ写像する。
曖昧Expectedは意味精度からだけ除き、F/QA/費用の分母は元どおり保持する。

- 支持Recall（Expected SのうちSとした割合）: 0.90以上。
- 非支持Specificity（Expected C/NSのうちC/NSとした割合）: 0.90以上。
- この設計では観測誤支持率/支持見落とし率の上限はそれぞれ10%。安全な自動運用や母集団誤り率10%以下の保証ではない。
- 3分類精度、二値精度、クラス別の分母/誤り数、QA/文書Group単位の不確実性も必ず併記する。
- 同じQAの順序/反復を独立標本として信頼区間を狭くしない。クラス分母0はnullで、自動通過や例の補充をしない。
  Known/Main/Calで必要なクラス被覆と不足時の扱いは、新Protocolに明示してから固定する。
- 旧15 QAの全42文/30条件・元のExpectedを保存した完全回帰を最終候補で一度行う。
  全84 Call完了と実行Health、上記意味基準を満たす前にMainへ進まない。
- 新規Main各20 QA・各10以上の完全比較、両言語全Label封印、独立品質採点、予約Calの確認も必要。
  判定基準は未使用結果を見てから調整しない。

0.90は従来の90%という意味精度の目安を、主指標に対応する両クラスへ対称に適用する設計判断である。
既存の失敗を通す値を逆算したものではない。実際、旧Q6回帰v8の観測部分は支持23/24・非支持13/16で、
非支持81.25%のため新設計でも不適合。旧v9は未知応答のため実行Health不適合である。
これらは全Run未完了の観測値であり、74/58予定分母に対する全体精度ではない。

旧v1の`critical_all_exact`/誤支持0を要求するGuardはそのまま保持する。
新Versionの判定経路を明示し、単にFlagやManifest Hashを書き換えて旧Guardを通さない。
Known採用、Main開始前/封印後、Calibration、最終Validatorまで同じ基準Versionを結び付ける。
旧v1拒否の回帰、Sと非Sの誤り/C↔NSだけの誤り/クラス不足/Health失敗の境界を実装Testで確認する。

## 4. 追加開発の打切り規則

この依頼後の新しい開発枠は、**最終追加候補は最大1個、開発推論は合計最大188 Completion試行、
Native Task経過秒和は最大4時間（先に到達した上限）**とする設計上限。
Runtime診断の生成はこの内数で最大24試行。生成0の入力/Hash/CPU検証はCompletionに数えない。
実行前に別事前登録へ残枠と停止規則を保存する。本書自体で新しいRunを開始しない。

188は診断最大24 + 形式最大10 + 必要時の従来全意味最大70 + 全既知回帰最大84の保守的な枠。
関連条件が同じなら既検証証拠を再利用し、実際の必要枠を小さく登録する。
人工例の重複を減らした新Smokeなら、既知16+人工27=43 Callが一つの設計例。
従来全70を実施したふりをせず、対象数と検証の種類を別記する。

開始前の全9B記録は851、旧未知2。旧上限920/今回未使用69/旧42・42・81・42は旧台帳として保つ。
新枠を登録する場合は別枠として最大追加188、開発累積最大1039を明示し、古い未使用を使い回さない。
188を各候補/各自動継続/各新チャットへ毎回付与しない。移行後も同じ消費台帳を引き継ぐ。
4時間は現在の約55秒/Callという実測に対する開発費用の目安であり、完走保証ではない。
所要時間の定義、進行中Callのタイムアウトと停止後監査も事前登録に含める。

順番は「CUDA原因の読取り調査→必要な環境修復/生成0→少数の関連Smoke→最終候補1回の全回帰」。
失敗した局所候補ごとに全70/84を再実行しない。Runtime障害をPrompt改善で処理しない。
上限や不適合に達したら新候補を追加せず、負の結果・未達要件・具体的な代替/判断点を示す。
自動的な予算拡張、閾値変更、追加QA、Goal完了宣言で解決しない。

## 5. Main/Calと最終規模

各20 QAのMainと別予約各20 QAのCalは維持する。現行1660 Call/言語、段階Session最大5新規QA、
QA全固定文の原子予約を保つ。追加開発188枠とMain/Cal予算は別である。
必要時間の見積りはJudgeだけでMain25.6〜33.8時間、同規模Cal込み51.2〜67.6時間。
入力/出力長の違う2群の平均を掛けた仮定で、上限/95%CI/総時間ではない。
初回生成/書換え/検索/起動/採点/待機も別に見積もり、実走前に総資源枠を記録する。
全体の納期・利用可能時間は未指定であり、勝手に72時間等の総上限を確定しない。

減らすなら最終EvaluationのNを資源・精度の根拠とともに決める。英語200問案の自動転用をやめ、
未使用Evaluationの結果や有意差を使わず、Group単位CIの幅と主/Cal実測で規模を判断する。
Main/CalのID、順序反復対照、失敗分母を削って収めることはしない。
追加Model比較やRQ3/RQ4の拡張は、Phase 11完了の必須条件へ増やさない。
RQ2の独立回答品質・費用評価は維持し、Fの揺れだけで卒論の結論を作らない。

## 6. 根拠と適用範囲

LLM Judgeの位置/長さ/自己選好や推論上の限界は既存研究でも扱われている。
[Zheng et al., NeurIPS 2023](https://arxiv.org/abs/2306.05685)。
これは本評価器の妥当性の証明ではなく、誤りを明示して独立検証する必要性を支持する一次資料である。
本書の90%/188回/4時間は当研究の目的と資源に対する設計判断であり、その論文から得た採用値ではない。

少数観測で誤り0でも真の誤り率0は証明できない。
[NISTの二項信頼限界](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbici.htm)も参照するが、
反復/順序条件が相関する本データへ独立二項区間をそのまま適用しない。
新基準を導入したこと、元の厳しいGateとは異なること、測定と一般化の限界を最終報告で明記する。
