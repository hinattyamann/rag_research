- 新規QA投入の終了: **2026-11-14 23:59:59 JST**。進行中QAは応答/費用を保存して終え、新しいQAを開始しない。以降の新Batchは開始しない。
- 採点/解析/資料化の期限: 2026-11-17 23:59:59 JST。120問が早く終われば追加せず完了する。
- 1 Batch/言語1,660 Native上限、全6枠で9,960。各Session新規5 QA、12時間/Session、72時間/Batch。待機・起動失敗も壁時間へ計上する。

- 初回512 Tokenの確定打切り、自然終了した書換え本文512 Token超過は、失敗Raw/費用を保持して次へ進む。書換え要求時は初回保持/書換え失敗。その他の未知/形式/通信/Native障害は再送せず保存・停止する。

## 自動工程と成果物

1. 日英各5 QAを交互に初回生成し、両言語20件がそろってから同様に内部評価/共通書換えを行う。
2. 日英の全匿名品質/全文Expectedを採点し、両言語を封印してから内部結果と結合する。採点設定はgpt-6.1-sol/high、実Serving Snapshot/履歴独立性/人手正解を仮定しない。
3. Batch別にQA内のO/R/D、Group Bootstrap（10,000/Seed42）、日英差、意味監査、品質遷移・改善見逃し・有害選択・方策品質/費用、既定5閾値の感度を集計する。
4. 4種のCSV・図のPNG/PDF/SVG、全選定QAの本文/Reference/実使用根拠/A/B/F/判断/Y/費用、採点・条件来歴、出典/利用条件、説明例、Manifest、標準ライブラリのオフライン検証入口を保存する。
5. Batch終了ごとに共有し、GitHubから取得し直した資料だけでHash・数値・原文・引用・欠測対応を検証する。
6. 最終的に**新規追加集合だけ**の統合結果も生成する。旧Main/Calは合算しない。Batch別も保持し、途中終了なら完了Batchに条件付けた結果と明記する。

成果は `papers/iciae2027/materials/cal_extension_v1/` と `reports/cal_extension_v1/`。選定済み追加120問に必要な原文/採点だけを、前回と同様の検証済み執筆資料としてGit共有する。全Corpus、モデル、未選定QA、認証情報、巨大ログは共有しない。

Git反映は開始、日英5 QAずつの処理完了、工程切替、停止、確定成果保存時。定時の1時間送信はしない。GitHub更新時刻は最後の区切りであり、収集の生存判定には使わない。ローカル状態は約30秒ごとに更新する。

著者はノートPCで追加資料を取得・照合し、日英原稿の方法/分母/図表/要旨/結論を同内容で更新する。弱まる結果も報告し、人手未確認・欠測・採点方式/時期差・出典未確定を保持する。教員レビューと投稿は別工程。
