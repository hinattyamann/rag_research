# 固定v23 CalのGPU起動失敗からの再開 v1

2026-10-31の事後的な収集制御の変更。研究対象のモデル出力に対する再試行ではなく、回答要求前のCUDA起動失敗だけを対象とする。

## 停滞と原因

Mainの40件処理、全日英匿名採点封印、解析・公開集計、Cal進行条件確認と事前登録は完了している。Calは英語初回20件、内部評価・書換え10件を完了し、日本語は未着手。10/31 16:03 JST、次の英語内部評価5 QAを開始するモデル読込みで停止した。

`en/internal/server-3.log`は29.01 MiBのcudaMalloc失敗とmodel loading errorを記録している。元の全33層GPU/Context12288/Batch128のモデルを読み込む際にGPUメモリが不足した。画面・アプリのGPU使用がある一方、従来の外側制御に起動前の空き確認がなかった。起動失敗を一般的な収集失敗として保存・停止したため自動再開されなかった。Token超過や新たな書換え欠測ではない。

失敗Receiptは約18.03秒。全255 Native記録が起動開始前に保存されたもので、現在の未知記録0、失敗起動で新しい回答要求0であることをHashと記録時刻で確認してから再開する。元のReceipt/Logとserver-3.logは保存する。

## 変更と限定

- 内部評価用GPUの空き7100 MiB、初回回答用3000 MiBを5秒間隔で3回連続確認して起動する。空き不足はwaiting_gpuと必要量/空き量を表示する。待機は1回最大3600秒か元の残り予算の短い方とし、無期限の待機を行わない。
- 生成前のモデル読込みCUDA OOMに限り、Native全件の集合・Hash不変/未知0、終了済み失敗Receipt、該当server Logを確認して再起動できる。最大2回の失敗退避、すなわち同じ5 QA段階で最大3回の起動まで。生成要求後・結果不明・別エラーは再送しない。
- 失敗起動・空き待ちの時間をCal累積72時間と各5 QA段階12時間の残予算から差し引く。成功済みの段階は再生成しない。Native自動再試行0、1660 Call/言語、20 QA/言語、主閾値0.7は不変。
- モデル/Prompt/Tokenizer/Runtime/全層Offload/Context/Batch/QA/採点基準は変更しない。Calの全匿名採点封印前に内部Fと品質ラベルを結合しない。
- 失敗server Logは成功CUDA証跡に数えず、起動失敗台帳と元Log/Receipt/Native Hashを別に検証し、費用監査へ残す。失敗Logを削除したり成功したように扱ったりしない。

## 配置・再開・監視

Calのprotocol.jsonは旧自動化Helperと品質ProtocolもHash固定しているため、旧固定Helperを上書きしない。修正版は専用Checkoutの別ディレクトリ`fixed_v23_automation_v2`へ配置し、Controller Revision6として追加封印する。旧18入力、Cal事前登録、Main封印・解析と既存Nativeの不変を確認する。

失敗した外側collect-cal Receiptを監査退避し、失敗した内側en-internal-2 Receipt/Logを同じcal-sessions内のstartup-failure名へ保存する。これにより費用を残したまま未処理の英語11件目から進む。GPU待ちへの移行/解除、工程切替/完了/停止をGitへ反映し、定時の反映は行わない。収集・空き待ちはCodex CLIを起動しない。

ブラウザ等のユーザーアプリを無断終了しない。空きが確保できるまではモデルを起動せず、GPU待ちと推論再開を区別して報告する。有限待機を超えた場合は理由を保存・公開して停止する。
