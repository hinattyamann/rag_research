## 研究室へ戻った時の使い方

1. 研究室PCでこのRepositoryを開く。旧チャットや別の実験を同時に再生しない。
2. 下のブロックを**新しいCodexチャット**へ貼る。必要なら本書と`docs/phase11_lab_weekend_goal.md`を添付する。Repositoryの相対Pathから読めれば添付は不要。
3. 最初の説明で、Git同期、既存プロセス、Model/Runtime/Rawの確認、新Goalのactive状態を確認する。電源・ネット・スリープと実行権限も出発前に確認する。
4. 日誌はCodexが実行した内容をJSTで追記する。ユーザーが過去の失敗を完了扱いに書き換える準備は不要。

## 最初の報告で見たいこと

- 同期したBranch/Commitと未Commit差分、すでに動いている実験の有無。
- 旧909試行/未知3件/v10不採用の保全と、どの新Protocol/台帳で再開するか。
- CUDA対策と意味判定改善を分けた最初の仮説・変更点・最小検証。
- 現在地、実行Handle/Run保存先、Goalの実状態、次の自動継続で行うこと。

人がいなくても進める指示だが、アプリ終了・停電・スリープ・ネット切断・利用上限・承認不能から必ず自動復帰する保証ではない。
起動前の状態確認で、そうした制約が分かった場合は出発前にユーザーへ具体的に説明する。
