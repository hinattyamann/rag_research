# Phase 10測定系の修正と再確認

2026年10月19日。初回20問の診断に基づくDevelopment上の修正。Phase 11の最終凍結ではない。

## 目的と変更の範囲

初回Pilotは、回答があるのに空Claimになる例、名前の由来・理由の抽出漏れ、調印と発効の時刻の混同、
書換えでも誤りを保持する例、Judgeの出力打切りを示した。これらを検査し、修正後の少数例で再確認する。
元の20問、既存のSource/Split、検索・初回生成条件、閾値0.7を変更しない。
修正RunからのFと旧RunのFを、同一の評価量として直接比較しない。

## 文単位の評価対象

抽出Promptだけを強化した試作v2でも、空港名の由来が抜けた。
候補v3では、初回回答の本文を文単位で保持する決定的な抽出へ変更する。
数値形式の引用マーカーと空白を除いて本文を再構成できることを検証する。
元回答以外を読まず、モデルによる言換え・取捨選択・事実訂正をしない。
単独の定型的拒否は別状態とし、拒否と事実を混ぜた回答は本文を残す。
未知の拒否表現は勝手に除外しない。引用と略語の判別・文分割には規則の限界がある。

これは**原子的な事実分解ではなく、複合した主張を含む文の支持判定**である。
全詳細が支持されて初めてsupportedとし、一部の明示的矛盾はcontradicted、支持不足はnot_supported。
Fはsupported文単位数/固定文単位総数となる。長い文と短い文の重みは同じで、
主張の細かさによる影響は限界とする。LLM抽出の抜けを順序効果に混ぜないことを優先する。
文の指示対象は固定の元回答・根拠の前後関係も参照する。

## 意味判定・書換え・予算

- v2は意味上の比較を指示するPromptを試す開発診断。失敗も残す。
- v3は短い理由・証拠を生成した後にLabelを選ぶ。同じDecoder順序・引用候補集合を全根拠順序へ適用する。
- 3Bでは意味誤りが残るため、v4は評価・書換えに公式Qwen2.5-7B-Instruct GGUF Q4_K_Mを候補として使う。
  初回生成は既存3Bのまま。モデル規模だけで改善を主張せず、同じ診断を通す。
  [公式固定Revision](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct-GGUF/tree/bb5d59e06d9551d752d08b292a50eb208b07ab1f)の
  2ファイルを公式SHA-256で検証し、専用Manifestへ保存する。Runtimeは既存b11433のWindows CPU。
  以後の「自己評価」はRAG内部の評価機構を指し、初回生成と同一のModelによる自己採点という条件には限定しない。
  複数の変更をまとめた測定系改訂であり、Modelだけの効果を分離したAblationではない。
- 引用は原文の320文字以内、理由120文字以内、各文の引用最大2件。
  長い文書は同じ原文の短い連続部分も引用候補にする。全文書は入力に残す。
- 補助Contextは12,288、Judgeの出力予約3,072、書換え512。入力＋予約を毎回検査し、超過時は失敗として保存。
  初回Baselineの4,096/512は変更しない。予約枠の増加は入力切詰めの許可ではない。
- 書換えは初回回答を未検証の下書きとして扱い、根拠から必要情報を確かめて誤り・不必要な拒否を修正する。
  元順序・同じ根拠・1候補共用・再検索なし・JudgeのScore/Feedback/Reference/Goldなしを維持する。

## 再確認前の完了基準

診断例は既知のDevelopment失敗例と人工的な支持/矛盾/支持不足の確認で、一般精度の推定標本ではない。
新しい5問は旧20問と以前の既知Titleを除き、同じSHA256選定規則で推論前に
[選定Manifest](../data/manifests/phase10_recheck_selection_manifest.json)へ固定する。

1. 事実回答の既知5例について、旧来の抜け（歌手、名前の由来、人物名、建設理由、アルバムの説明）を保持する。
2. 時刻・数値・否定・関係の明確な人工12例で、支持/矛盾/支持不足の期待Labelを確認する。
   時刻誤りの自然例と、実使用根拠に説明があるグラナの自然例も監査する。
3. 調印時刻の訂正と、根拠に情報があるのに拒否していた回答の見直しを実出力で確認する。
4. 旧7 Claimの長い例を含め、診断・再確認の入力超過と出力打切りがないことを確認する。
5. 新規5問で順序5条件と元順序5反復（共用1回、最大9回）、書換え1回を実行する。
   3問以上が完全比較可能、Judge失敗0を実行面の目安とする。拒否は比較不能として保持し補充しない。
   全回答の文単位網羅性を監査し、外部AI品質採点を全候補で固定した後に内部F/判断と照合する。

反転・品質改善の発見は新規5問の合格条件にしない。修正後も残る意味誤判定を隠さず、
限界の程度によって追加修正かCalibrationでの検証事項かを判断する。
新規5問の結果を見て修正する場合、その5問を新しい未見確認と呼び直さない。
Evaluationは読まない。人手採点の追加募集はしない。
